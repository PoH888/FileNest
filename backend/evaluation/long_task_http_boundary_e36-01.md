# FileNest 第 36 课：长任务 HTTP 边界（E36-01）

## 目的

本报告只确认哪些现有工作负载已经有证据超过普通同步 HTTP 请求的合理承载范围，为后续任务模型设计提供输入。它不定义 Job、Attempt、进度、取消或重试语义，也不引入后台执行器、Redis、Celery 或 V1 file monitor。

## 判定规则

这里的“5 秒”是 FileNest 当前本地交互产品的同步响应预算，不是 HTTP 协议的硬限制：

- 代表性规模的中位数超过 5 秒，或同一规模的全部样本均超过 5 秒，判定为已确认长任务；
- 只有部分样本超过 5 秒，记录为存在长尾，但不据此把所有规模都强制后台化；
- 全部已测样本均低于 5 秒，保留同步路径；以后只有新证据才能改变结论。

## 现有证据

证据来自 `scale_measurements_e35-02.json`、`scale_measurements_e35-03.json` 和 `scale_measurements_e35-04.md`，每个规模重复 3 次。

| 工作负载 | 规模 | 样本范围 | 中位数 | 结论 |
| --- | --- | ---: | ---: | --- |
| 工作区扫描与 FileEntry 持久化 | 100 文件 | 176.494–183.033 ms | 179.850 ms | 保留同步 |
| 工作区扫描与 FileEntry 持久化 | 1,000 文件 | 1,548.058–1,564.938 ms | 1,551.430 ms | 保留同步 |
| 工作区扫描与 FileEntry 持久化 | 10,000 文件 | 14,644.923–14,762.789 ms | 14,742.750 ms | 已确认长任务 |

## 当前结论

1. **大规模工作区扫描已确认超过同步 HTTP 预算。** 当前 `POST /api/v1/workspaces/{workspace_id}/scan` 直接在请求中完成扫描和持久化；10,000 文件的三次样本全部超过 14 秒，因此该行动是后续最小后台任务基线的真实候选。
2. **大规模文档索引已确认超过同步 HTTP 预算。** 8,000 文档的三次样本全部超过 25 秒，最高超过 80 秒；如果该流程接入 HTTP，它应作为后台任务候选。800 文档出现一次 10 秒长尾，说明是否后台化应结合规模，而不是把所有文档操作统一异步化。
3. **文件搜索不需要后台化。** 现有最大规模仍为毫秒级。
4. **真实模型 Agent 请求尚不能判定。** 现有规模报告使用 FakeModelClient，不包含模型网络延迟、供应商排队或限流；不能用该数据证明真实 Agent 请求适合同步，也不能反向证明必须后台化。
5. **批量安全执行和撤销尚不能判定。** 当前没有代表性规模耗时证据，保持现状，不提前纳入后台系统。
6. **V1 file monitor 不属于本任务的已证实 HTTP 长任务。** 它是持续监听能力，是否接入必须由独立产品需要和资源证据决定。

因此，后续任务系统只把“大规模工作区扫描”和“大规模文档索引”作为已经由测量支持的首批候选。其他行动继续同步或保持未决定，直到出现新的代表性证据。

## 当前明确不做

- 不定义 Job、Attempt、进度、取消和重试模型；
- 不实现线程、进程、队列或 worker；
- 不引入 Redis、Celery 或其他分布式基础设施；
- 不接入 V1 file monitor；
- 不修改现有 HTTP 路由或业务行为；
- 不新增测试矩阵，直接复用既有规模测量与测试证据。

## 证据限制

- 测量来自本地 Windows、生成式固定工作区和临时 SQLite，不等同于生产压测；
- 每个规模只有 3 次样本，足以确认当前明显差异，但不能代表完整延迟分布；
- Agent 测量使用 FakeModelClient，不能外推到真实模型调用；
- 5 秒预算是当前可撤销的产品边界，后续可由真实用户体验、部署超时或新测量调整。
